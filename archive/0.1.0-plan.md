# 0.1.0 — SIRDS round-trip: generate with simple noise, reverse to heightmap + pattern

Self-contained plan for implementation from scratch (no reference to prior steps).

## Goal

One file://-friendly page that does the full round trip:

1. build a height map (presets + parameters),
2. generate a SIRDS from it with simple (white) noise,
3. reverse the SIRDS using pixels only: recover height map and base pattern,
4. show input / SIRDS / recovered / error side by side.

Prove the pipeline with automated node tests (round-trip metrics), since visual
inspection of noise images is unreliable.

## Reference material

- Generator port source (keep as provenance): `vendor/gf-source.html`, from
	https://github.com/luncat8/SIRDS-stereo-image/blob/main/gf.html
- Thimbleby, Inglis, Witten, "Displaying 3D Images: Algorithms for Single Image
	Random Dot Stereograms" — the symmetric `same[]` linking algorithm the
	generator follows (plus the non-linear separation function, not used here):
	https://harold.thimbleby.net/sirds/ieee3d.pdf
- Kekoa Proudfoot, "An Autostereogram Decoder" (talk + `decode.c`, 2003) —
	classic reverse: per-pixel winner-take-all block matching between the two
	halves of a trial separation; the reference for section "Reverse":
	https://graphics.stanford.edu/~kekoa/talks/gcafe-20030417/
- Neural Magic Eye (arXiv:2012.15692) — CNN with disparity-convolution layer,
	self-supervised, current best quality on natural autostereograms. Related
	work only: needs PyTorch + training, violates the runtime rules:
	https://github.com/jiupinjia/neural-magic-eye
- General stereo-matching literature (WTA + aggregation, scanline DP with
	ordering constraint and occlusion cost, e.g. Ohta–Kanade, Birchfield–Tomasi)
	is the fallback toolbox if plain WTA is too noisy.

## Forward model (exact, to be ported)

Parameters: `P` pattern period (default 100, UI range 60..320), `depthScale`
(default 20, UI range 5..160), `noiseScale` grain (default 2, UI range 1..16),
`seed` (constant 1).

Per row of the height map (`z` in 0..1, red channel of the depth image / 255):

	s(x) = max(1, floor(P - z(x) * depthScale))        // stereo separation

	same[x] = x for all x
	for each x:  l = floor(x - s(x) / 2),  r = l + s(x)
	             if l >= 0 && r < w: same[r] = l      // later x overwrites

	fill the row left to right:
	  free pixel (same[x] == x)  -> pattern noise at (x, y)
	  linked pixel               -> copy the (already resolved) value at same[x]

Pattern noise ("simple noise", b/w):

	nx = floor(x / noiseScale) * noiseScale, ny likewise   // grain quantization
	v  = frac(sin(nx * 12.9898 + ny * 78.233 + seed * 11.17) * 43758.5453123)
	gray = v > 0.5 ? 255 : 0

Consequences the reverse must respect:

- Pairing is centered on the depth pixel x and, for odd s, is NOT a symmetric
	split: l = x - ceil(s/2), r = x + floor(s/2). The reverse must use this exact
	pairing (see findings-pitfalls-skills.md).
- Colors are exact copies along chains; at the true s the match residual is 0
	away from seams. Residual doubles as confidence.
- A pair only exists when both endpoints are inside the row (l >= 0, r < w), so
	the depth of roughly the first and last ceil(sMax/2) columns is never encoded
	at all. Recovery there is undefined and must be masked, not faked.
- When s grows between adjacent x, right() skips columns; those columns get
	fresh noise (the known "echo"/seam artifact) and carry no correspondence.
	When s shrinks, a later center overwrites an earlier one's right endpoint, so
	the earlier center's pair becomes a "phantom" whose residual is no longer 0.
	Both cases produce low-confidence pixels, not fake depth.
- Depth is quantized to the integer s values; the finest recoverable z step is
	1/depthScale. Tests compare in s-space (or against quantized z), never
	against the continuous input height.
- `z * depthScale` is a dyadic rational on the 8-bit z grid, so float error at
	exact integers decides the floor the wrong way and breaks the s -> z -> s
	inversion. `sFromZ` adds a 1e-9 nudge for that reason; it is the one place
	the quantization lives.

## Reverse (0.1.0: winner-take-all block matching)

Read the red channel of the RGBA input (the generator writes the same value to
R, G and B, so one channel is exact for our images and still a valid pattern
channel for color noise).

Per pixel x on each row, search every integer s in [sMin, sMax]
(known params: [max(1, P - depthScale), P]; unknown params: user-supplied):

	l = x - ceil(s/2), r = l + s
	cost(s) = SAD of window (2*winX+1) x (2*winY+1) centered at (l, y) vs (r, y)

	s* = argmin cost,  z = clamp01((P - s*) / depthScale)

Defaults: winX = 4, winY = 2 (9 x 5; binary noise needs more support than the
7 x 3 of decode.c). Pixels whose best residual exceeds `confRel` are marked
low-confidence — these are seams and depth edges. Default `confRel` is 0.02,
just under the cost of one mismatched pixel in a 9 x 5 window (1/45), so at the
default a "confident" pixel is a pixel-exact match; raise it for lossy (JPEG)
uploads, where exact copies no longer survive.

Outputs: `s` map (0 = unevaluable), `z` map (0 where unevaluable),
`conf` map = 1 - residual/(255 * winArea), so conf === 1 means a pixel-exact
match. Metrics are always reported on the raw s map; display smoothing, if
ever wanted, belongs in the page, not in the core.

### Two rules that make the argmin correct (both measured, see worklog)

1. **Smallest s wins ties.** In a region of constant s the row is periodic with
	that period, so every multiple k*s that stays inside [sMin, sMax] also scores
	cost 0 (measured: P=100, depthScale=60, a z=1 half-plane yields cost 0 at both
	s=40 and s=80). Searching s ascending and updating the best only on strict
	`<` picks the true s; the opposite tie-break recovers 80 instead of 40.
2. **Record a link only when it is confident.** The reverse also rebuilds the
	generator's per-row link table (parent[r] = l, last write wins, exactly like
	the forward pass) because pattern recovery walks those chains. A link is
	recorded only when residual <= confRel: in border bands the best available s
	is wrong but noisy, and recording it corrupts the chain (measured: flat input
	pattern strip 91.6% valid with all links recorded, 100% valid and 100% correct
	when only confident links are recorded).

For uploaded SIRDS without known params: primary output is the s map (inverse
shift), normalized for display as (sMax - s)/(sMax - sMin); true z needs
depthScale, which the UI exposes as an input, not a guess.

Why WTA first: the generator copies pixels exactly, so matching is much better
posed than natural stereo; residual 0 identifies the true s in flat regions.
Scanline DP (ordering constraint + occlusion cost) and vertical smoothing are
the documented upgrade path if WTA proves noisy at edges — kept out of 0.1.0
to keep the pipeline measurable and small.

## Pattern recovery

Definition: the base pattern is the P-wide noise strip that, repeated at
separation P, reproduces the far background — i.e. the noise the generator
would print with z = 0. Because the noise field is a function of absolute
position, that strip is exactly the samples taken at origins 0..P-1.

Extraction: from the reverse's link table, walk each row's chains
(origin(p) = parent[p] === p ? p : origin[parent[p]], a single left-to-right pass
because parent < p always) to get every pixel's chain origin. A pixel's value is
a sample of the noise field at (origin, y). Collect samples with origin < P into
a P x h strip; first sample wins, holes stay empty and are reported through a
`patternValid` mask. On flat input the strip equals the first P columns of the
SIRDS exactly — that is the unit test for pattern recovery. (Samples with
origin >= P are fresh seam noise, not pattern.)

No build step, no modules, no network at runtime; modern browsers only;
single-tab indent, LF; no allocations inside per-row/per-pixel loops
(`same`, gray row, column-SAD, best-cost buffers and the link table are
allocated once per call by a scratch object).

## Core API (sirds.js)

	params: { P, depthScale, noiseScale, winX, winY, sMin, sMax, confRel, seed }

	hashNoise(x, y, seed)                -> 0..1
	patternGray(x, y, params)            -> 0 | 255
	depthPreset(kind, w, h, outU8)       -> fills height map
	                                       ('flat' | 'shapes' | 'torus' | 'ramp')
	createScratch(w)                     -> reusable buffers for generate/reverse
	createReverseOut(w, h, params)       -> { s, z, conf, pattern, patternValid }
	generateSirds(heightU8, w, h, params, outRGBA, scratch)
	reverseSirds(rgba, w, h, params, out, scratch)
	sFromZ(z, params) / zFromS(s, params)   // the single place the quantization lives

All functions pure over typed arrays. Depth presets are defined relative to w/h
so tests can use small images: `flat` (all zeros), `shapes` (mid-gray square +
white circle), `torus` (smooth ring gradient), `ramp` (linear gradient, worst
case for seams, best case for metric sanity). A `text3d` preset stays in
index.html only (needs canvas text).

### Reverse inner loop (measured budget)

For each row and each s, build a column-pair SAD once
(colSAD[c] = sum over the vertical window of |I(c) - I(c+s)|), then slide the
horizontal window one column at a time (add the entering column, subtract the
leaving one) so the per-(x, s) work is O(1). This is ~5x faster than the naive
quadruple loop and keeps 640 x 400 at ~110 ms; the naive version is kept as the
reference in tests/run.js and both must agree pixel for pixel.

## Tests (node tests/run.js)

Independence rule: expected s values are computed inside the tests from the
documented formula, not imported from sirds.js, so formula drift is caught.

1. quantization: sFromZ/zFromS invert each other on the integer s grid.
2. determinism: same height + params -> byte-identical SIRDS.
3. flat depth: recovered s == P and conf === 1 on every evaluable interior
	pixel (100%); regenerating from the recovered s map reproduces the input
	SIRDS on the interior.
4. shapes: >= 95% of confident evaluable pixels have |s_rec - s_gt| <= 1;
	exact-match rate reported.
5. torus (smooth): >= 90% of confident evaluable pixels within 1; ramp: mean
	|z_rec - zFromS(s_gt)| <= 0.25/depthScale (raw z MAE reported too).
6. seam masking: on `shapes`, outside a band of winX + ceil(maxJump/2) + 1 px
	around a depth discontinuity the recovery is exact (100%) and the
	low-confidence rate is ~0; inside a 2 px band >= 90% are low-confidence.
7. pattern: flat-depth recovery strip == generator noise strip (first P cols),
	100% valid cells and 100% correct.
8. window sensitivity: case 4 with winX 2 vs 4 — record both, assert the
	stricter threshold on the default only.
9. fast vs naive: the incremental matcher and a naive SAD matcher in the test
	file agree on s and residual for a small image at every preset.
10. degenerate separations: with depthScale > P/2 (so a multiple of the true s
	is also in range) the smallest-s tie-break recovers the true separation on a
	flat half-plane.

Metrics printed per case: exact %, within-1 %, z MAE, confident %. Any
assertion failure exits non-zero. Numeric baselines that turn out
unreachable are adjusted in the worklog with the measured value — the
assertions, once locked, are never weakened silently.

## Visual lab (index.html)

Layout, left to right:

- controls: depth preset (shapes / torus / ramp / text3d / flat), sliders P,
	depthScale, noiseScale, winX/winY, confRel, buttons Generate + reverse,
	Re-generate from recovered; SIRDS file input (drop or pick) for external
	images -> reverse-only path. The reverse-only path reuses the same P and
	depthScale controls as the assumed search range, so there is no second set
	of inputs to keep in sync.
- depth map canvas (input)
- SIRDS canvas (generate output / uploaded input)
- recovered height canvas, tinted continuously by the match residual (pure
	gray = pixel-exact match, pure red = none)
- error canvas |s_rec - s_gt| (round-trip mode only)
- recovered pattern strip

Reverse runs synchronously at full size (measured ~110 ms at 640 x 400); no Web
Worker (file:// worker restrictions) and no reduced-size preview pass, because
resampling noise destroys the exact-copy property the matcher relies on. No
per-frame allocations if animation is ever added later. Guide dots from the
generator UI are skipped (out of scope); the page states the viewing hint in a
static line.

## Performance

Budget: 640 x 400, s-range 21, 9 x 5 window. Naive quadruple loop is ~600 ms;
the column-pair SAD with sliding horizontal window is ~110 ms and generation
takes ~10 ms (both measured in node 22, same machine; per-case numbers in
experiments/logs/accuracy-baseline.md). Cost scales linearly with
P - depthScale, so a deep image with a large P is the slow corner (P=160,
depthScale=80 -> ~490 ms).

## Acceptance criteria

- `node tests/run.js` passes all 10 cases.
- index.html does generate -> reverse -> visualize over file:// with no
	network and no build.
- Round trip at defaults reproduces the height map to the quantization limit
	everywhere except masked seams and border bands; the recovered pattern
	regenerates the same background noise.
- findings-pitfalls-skills.md contains the pairing rule, the exact-copy
	confidence trick, the multiple-of-s tie-break rule, and the Math.sin-hash
	caveat (see that file).
