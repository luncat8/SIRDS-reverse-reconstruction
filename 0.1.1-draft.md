# 0.1.1 — draft

The weakest part of 0.1.0 is smooth gradients: at the defaults the torus
recovers 90.8% exact / 76.8% confident, against 98.4% / 95.2% for shapes.
The confidence map is already correct there — the failures are ambiguity
between neighbouring separations, not failed detection, so the fix belongs in
the regularisation step, not in the cost.

Candidates, in order of expected value per unit of work:

1. vertical regularisation — a 3-5 row median on the s map. Cheap, no new
	parameters beyond a width, and it should convert most of the remaining
	ramp error. Must not touch the exact-match invariant: run it on a
	separate map so the raw maps and the metrics stay intact.
2. left-right consistency — reject an s whose pair disagrees with the pair
	implied by the neighbouring pixel's s, which is the ordering constraint
	the scanline DP literature uses (Ohta-Kanade, Birchfield-Tomasi).
3. automatic P estimation by row autocorrelation, so uploaded SIRDS do not
	need the period typed in. This unblocks the real use case (an image from
	somewhere else) and is the only item here that adds a user-facing
	capability rather than better numbers.

Measure with `node experiments/accuracy.js` before and after; the baseline
table in `experiments/logs/` is the only accepted evidence.

Not now: colour / simplex / stripe patterns, animation, neural decoding.
